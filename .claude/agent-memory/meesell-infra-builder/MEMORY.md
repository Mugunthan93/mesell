> **HOW THE GUARD WORKS (reusable design for future route/nav contracts):**
> 1. **Route table is DERIVED, never hardcoded** (so it stays correct as routes change). Parse `apps/shell/src/app/app.routes.ts` as the root; for each route node carrying `loadChildren: loadRemoteRoutesWithFallback('<remote>','<expose>')`, resolve `<remote>+<expose>` → the route-array FILE via that remote's `apps/<remote>/federation.config.js` `exposes` map, then splice the target file's `path:` literals under the parent node's path prefix. Follow ONE barrel re-export hop for exposes that point at a `public-api.ts` (`export { BILLING_ROUTES } from './billing.routes'`). Result on develop = 18 canonical patterns (`/catalogs/:id/edit|images|pricing|export`, `/catalogs/new|live`, `/billing/plans|account`, `/dashboard`, `/login`, `/signup`, `/otp-verify`, `/onboarding`, `/profile`, `/categories/browse`, `/`, `/catalogs`, `/billing`).
> 2. **Extract every static nav literal** across `apps`+`libs` (`.ts`+`.html`, EXCLUDE `*.spec.ts`/`*.routes.ts`/comments): `router.navigate([...])`, `navigateByUrl('...')`, `routerLink="..."`, `[routerLink]="'...'"`, AND inline config literals `routerLink: '...'` + `route: '...'` (the nav-item/menu/step source that feeds `[routerLink]="item.route"`). The `route:` extractor is the highest-value one — a typo'd MENU route is the exact "founder clicks dead nav item → logout" bug; sidebar.nav-groups.ts + shell.component.ts `route:` literals ARE validated.
> 3. **Resolve:** variable segments (`id`, `this.productId()`) → `:param`; literal segments stay literal; the result must match a defined pattern. A literal trailing segment with no matching route (like `'preview'`) = DEAD. A navigate whose FIRST element is a variable (`navigate([routeVar])`) is unanchored → dynamic.
> 4. **exit 1 + name each dead `file:line → target`**, else exit 0 ("OK: N static navigations, all resolve"). Fully-dynamic targets (`navigate(routeVar)`, `[routerLink]="item.route"`, `[routerLink]="route()"`, `routerLink: item.routerLink`, `route: s.route`) are printed as `UNVERIFIABLE (dynamic): file:line` and NEVER fail the build (6 such on develop — the residual surface).

> **TWO PARSER BUGS I hit + fixed (will recur if you write another route-aware guard):**
> (a) **Federation expose paths resolve from the ANGULAR WORKSPACE ROOT = `frontend/` (where angular.json + the federation configs live), NOT the repo root.** I first did `join(feRoot(),'..',path)` (up to repo root) → every `./apps/...` expose resolved to a non-existent path → the route table was MISSING all loadChildren-expanded routes (only 12 of 18; `/catalogs/new`, `/billing/plans`, etc. absent). Fix: `resolve(join(feRoot(), wsRelPath))` since `feRoot()` IS `frontend/`. ALWAYS sanity-dump the derived route table (`--routes` flag) before trusting a nav check — an incomplete table = false PASS (a dead route slips through).
> (b) **A `loadChildren` (or any nested-object key) must be read at the object's OWN brace-depth, not by scanning the whole object body.** My first `parseRouteObject` regex matched `loadChildren` anywhere in the body → the protected-parent node (`path:''` with 8 children) wrongly inherited its `catalogs` CHILD's `loadChildren` → CatalogRoutes got expanded at BOTH `/catalogs/*` (correct) AND root `/*` (bogus `/new`, `/:id/edit`, `/live`). Fix: a depth-0 `ownKeyIndex(text, from, to, re)` helper (track `{[(`/`)]}` nesting, only match a key at depth 0) used for `path:`, `loadChildren:`, AND `children:`.
