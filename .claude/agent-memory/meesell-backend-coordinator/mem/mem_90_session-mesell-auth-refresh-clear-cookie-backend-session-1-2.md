- **The bug class (durable lesson):** the global `core/errors._meesell_error_handler` returns a BRAND-NEW `JSONResponse`, so ANY `Set-Cookie` (or other header) set on the FastAPI-injected `response` BEFORE re-raising a `MeesellError` is DISCARDED. Pre-fix `auth_refresh` did `_clear_refresh_cookie(response); raise` → the Max-Age=0 clear-cookie never reached the browser → stale `refresh_token` persisted after a rejected/replayed refresh. **General rule: if a route must emit a header on an error path, it CANNOT rely on the global handler — it must build the JSONResponse itself (option a) or the header is lost.**
- **Fix (option a):** in `auth_refresh`, on `except RefreshInvalidError as exc`: call `_clear_refresh_cookie(response)`, then rebuild the 401 envelope via `core.errors._build_envelope` + `_resolve_message_id` (reusing the SAME builders as the global handler), wrap in `JSONResponse(status_code=exc.status_code, content=envelope)`, copy `response.headers.getlist("set-cookie")` onto it, return. Bypass is scoped to THIS exception in THIS handler only.
