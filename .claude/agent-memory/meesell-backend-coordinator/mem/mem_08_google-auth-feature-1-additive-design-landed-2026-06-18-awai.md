### google-auth (Feature 1 additive — DESIGN landed 2026-06-18, awaiting founder ratification)
- [docs/plans/google_auth/GOOGLE_AUTH_DESIGN_BACKEND.md] — authoritative backend design for Google Sign-In (GIS ID-token flow). DESIGN ONLY, no code until founder ratifies §A amendment. Key facts learned/decided:
  - **Founder-locked constraints:** DUAL IDENTITY (phone OR Google OR both → `iam.users.phone` becomes NULLABLE, `google_sub` + `email` become identity keys); flow = GIS ID-token (FE gets Google credential JWT, BE verifies vs Google certs, BE issues OUR access JWT + refresh cookie; NO server-side auth-code/redirect).
  - **Recommended schema:** identities INLINE on `iam.users` (NOT a separate table for V1) — add `google_sub VARCHAR(255) UNIQUE nullable` + `auth_provider VARCHAR(20) default 'phone'`, widen `phone` to NULL, add UNIQUE on existing `email`, + CHECK `phone IS NOT NULL OR google_sub IS NOT NULL`. V1.5 normalize to `iam.identities` if a 3rd provider lands.
  - **Endpoint:** `POST /api/v1/auth/google/verify`, body `{credential}`, response = `VerifyOtpResponse` shape (access_token+expires_in) + Set-Cookie via existing `_set_refresh_cookie` (cookie format UNCHANGED). Rate-limit 20/h per-IP. Feature-flagged `FEATURE_GOOGLE_AUTH_ENABLED` (default off → route NOT mounted so §17 count unchanged until enabled).
  - **Linking rule (the crux):** (1) match google_sub→login; (2) else match VERIFIED email→LINK google_sub onto existing phone user; (3) else create Google-only user (phone NULL). 409 GoogleIdentityConflictError if email belongs to a DIFFERENT google_sub. Edge cases 1-7 tabulated (email-changed keeps stored email; phone→existing-Google linking DEFERRED to V1.5; IntegrityError race → single retry).

Use `google.oauth2.id_token.verify_oauth2_token(credential, Request(), audience=CLIENT_ID)` — enforces sig/iss/aud/exp in one call; we add `email_verified==true` gate.
