# Frontend testing quirks

PrimeNG, signal, and federation-aware mock patterns + the pitfalls that bite in
Angular unit tests. Append a note whenever a TestBed setup surprises you.

## Seeded from prior project memory (2026-06-22)
- **PrimeNG + NG0201:** a component that toasts needs a `MessageService` provider in
  the TestBed — a missing one throws NG0201 (seen live in `app.spec.ts`).
- **Signals vs OnPush:** assert AFTER both `flushEffects()` and `detectChanges()`;
  asserting before either reads stale DOM.
- **Federation-aware mocks:** the shared `@mesell/core` `AuthService` is a
  cross-remote singleton at runtime — in a unit test always provide a fresh spy,
  never the real singleton, so auth state doesn't leak between tests.
- **Never load a real remote in a unit test** — mock the loader seam; federation
  wiring belongs to E2E.

## QA Wave 1 learnings (2026-06-22)

- **TS2352 double-cast pattern:** when an interface has no index signature, `obj as Record<string, unknown>` fails with "insufficient overlap". Fix: cast via `unknown` first: `obj as unknown as Record<string, unknown>`. This is the safe escape hatch for probing for absent keys on typed objects.
- **TS2367 narrowed-literal comparison:** a `const x: 'foo' = 'foo'; x === 'bar'` comparison is a TS error because the types have no overlap. Fix: `(x as string) === 'bar'` to relax the check while keeping the runtime assertion. The test intent (prove a value is NOT something) is preserved.
- **Functional guard testing pattern (Angular 21):** use `TestBed.runInInjectionContext(() => myGuard({} as never, {} as never))` to run a `CanActivateFn` in a DI context without navigating the real router. Provide the `Router` via `provideRouter([...routes])` so `router.createUrlTree(['/login'])` can produce a proper UrlTree. Verify the result is a `UrlTree` instance and check `.toString()` for the path.
- **Runner is Vitest (not Karma):** `@angular/build:unit-test` emits `.spec-*.js` chunks; test discovery uses `include` patterns relative to `sourceRoot (src/)`. Pre-test `tsc --noEmit -p tsconfig.spec.json` is a fast way to detect TS errors before paying the full build cost.
- **Pre-existing non-deterministic failures (refresh.interceptor i/j/k):** these tests use the real AuthService with `setupReal()` and two concurrent HTTP controllers, which creates async races. They pass ~60% of runs. Document as pre-existing; do NOT attempt to fix in the test-writer lane (they require feature code changes to AuthService's finalize() race guard — file back to coordinator).
- **ng test --include does not work with native-federation buildTarget:** only `frontend` and `mfe-billing` have `@angular/build:unit-test` test targets. Other remotes' specs are included via the `frontend` project's `include` glob (`../../**/*.spec.ts`). Never add `--include` flags for scoping within a project — it breaks with native-federation `buildTarget` warning.

## QA Wave 2 learnings (2026-06-22)

- **fire-and-forget logout POST pattern (CRITICAL):** `AuthService.logout()` and `AuthService.forceLogout()` both call `this.authApi.logout().subscribe({ error: () => {} })` — a fire-and-forget `POST /api/v1/auth/logout` that stays open in `HttpTestingController`. Any test that calls `logout()` / `forceLogout()` in setup or teardown WILL trip `httpMock.verify()` unless drained first. Fix: `controller.match('/api/v1/auth/logout').forEach(r => r.flush(null, { status: 204, statusText: 'No Content' }))` BEFORE calling `verify()`. This pattern applies in:  `afterEach` (global), `makeFixture()`, and anywhere else `logout` is called.
- **Angular global reset hook conflict:** Angular's `testing.mjs` registers global `beforeEach`/`afterEach` hooks via `getCleanupHook()` that auto-call `TestBed.resetTestingModule()`. Manual local `TestBed.resetTestingModule()` calls in a spec's own `beforeEach`/`afterEach` create ordering conflicts: "Cannot configure the test module when already instantiated" errors cascade to OTHER spec files (not just the file with the manual reset). Remove ALL manual `TestBed.resetTestingModule()` calls from `beforeEach`/`afterEach` — the Angular build unit-test runner handles this globally.
- **REFRESH_DEBOUNCE_MS = 2000ms cross-context backstop:** `AuthService.refreshShared()` has a debounce guard: if a token exists AND `Date.now() - _lastRefreshAt < 2000`, it returns `of({access_token: currentToken})` WITHOUT an HTTP call. A test that triggers two refresh cycles synchronously (or within 2s) will see the second cycle short-circuit — `expectOne('/auth/refresh')` throws "no matching requests found". Fix: temporarily mock `Date.now` to return `realDateNow() + 3_000` BEFORE the second cycle, restore in `finally`.
- **`controller.match()` is the safe non-throwing alternative to `expectOne()`:** `HttpTestingController.match('/path')` returns all matching requests as an array; it does NOT throw if no requests match (unlike `expectOne` which throws). Use `match` for draining fire-and-forget or optional requests; use `expectOne` only when you intend to assert the request MUST exist.
- **provideRouter stub must include ALL navigation targets:** any call to `router.navigate(['/path'])` that matches no stub route causes Angular to emit `NG04002: Cannot match any routes`. This error does NOT crash the test but poisons the error log and can cascade to other suites. Include ALL routes a component might navigate to in the `provideRouter(...)` stub: `[{path:'login',children:[]},{path:'dashboard',children:[]},{path:'onboarding',children:[]},{path:'otp-verify',children:[]}]`.
- **Content-projection test pattern (`<ng-content>` slots):** to test that a component projects host content, create a host wrapper component (`@Component({standalone:true, imports:[ComponentUnderTest], template: '<comp-under-test><p class="projected">text</p></comp-under-test>'}) class HostWrapper {}`) and call `TestBed.createComponent(HostWrapper)`. Then assert `hostEl.querySelector('.projected')` exists. This works within the SAME `TestBed.configureTestingModule` session after `imports: [ComponentUnderTest]` is already provided.
- **`ng test frontend` (shell project) is the umbrella runner for all specs:** the `frontend` project's `angular.json` test include `../../**/*.spec.ts` (from `apps/shell`) resolves to the workspace root `frontend/`, picking up ALL `apps/**` and `libs/**` spec files. The `mfe-billing` project's includes (`../../apps/**/*.spec.ts`, `../../../libs/**/*.spec.ts`) also cover everything but are resolved differently. Use `ng test frontend` as the authoritative run.
- **FE-AUTH-10 requires BOTH interceptors in the chain:** the `forceLogout()` call on refresh-exhausted 401 lives in `refreshInterceptor`, not `errorInterceptor`. To test the terminal path through the error interceptor, configure TestBed with `withInterceptors([refreshInterceptor, errorInterceptor])` (in that order). Both interceptors are `HttpInterceptorFn` functional interceptors — they compose via Angular's `withInterceptors([...])`. The `AuthService` and `AuthApiService` must also be provided (real, not spied) so `refreshShared()` and `forceLogout()` work; spy on `forceLogout` AFTER injection.
