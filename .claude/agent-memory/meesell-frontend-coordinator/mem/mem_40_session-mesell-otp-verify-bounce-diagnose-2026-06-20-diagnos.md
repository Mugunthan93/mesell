## Session mesell-otp-verify-bounce-diagnose — 2026-06-20 — DIAGNOSIS (read-only): OTP Verify fires no network + bounces to /login

- **SYMPTOM (founder, local all-static dev stack, develop, incognito):** phone → OTP page renders → enter `000000` → click Verify → NO network call, NO console error, redirect to /login. Hard-reload+incognito did not help.
- **PRIME SUSPECT (the ONLY no-network redirect to /login on the /otp-verify route):** `otp-verify.component.ts` ngOnInit L161-180 — if `phone` absent from BOTH `router.getCurrentNavigation()?.extras?.state` AND `history.state`, it does `void this.router.navigate(['/login']); return;` (L176). No guard on /otp-verify route; `onSubmit` ALWAYS fires `authApi.verifyOtp` (a network call) when reached, so a no-network bounce CANNOT come from onSubmit → it is the ngOnInit guard. forceLogout()/refresh-401 all involve a network call, so excluded.
- **ROOT CAUSE RANK:** #1 lost pending-phone state (history.state.phone dropped between login push-nav and otp-verify remote-chunk instantiation) — HIGH. #2 federation singleton (multiple AuthService) — LOW for THIS symptom (login+otp-verify are the SAME remote mfe-auth; phone travels via history.state NOT AuthService). #3 broken handler — RULED OUT (handler fires a network call). 
- **WHY #1 despite #308 fix being present:** #308 (commit 6b6f66f, IN this tree + develop) reads history.state as fallback. history.state IS preserved by client-side pushState on the SPA-fallback static server. BUT a FULL PAGE RELOAD between steps (Native Federation remote-load, or a re-instantiation triggering a 2nd ngOnInit) wipes the router-set state → ngOnInit bounces. The "renders then bounce on Verify" wording = on this load ngOnInit found a phone & rendered; the bounce is a 2nd ngOnInit with phone gone.
- **DEVELOP-WIDE:** otp-verify/login/auth.service byte-identical to origin/develop (git diff empty). NOT worktree-specific.
